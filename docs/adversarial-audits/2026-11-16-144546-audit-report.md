## Findings 详情

### [P0] AA-CONC-001 — 同一实例并发调用会互相吞掉响应 — `transport/mailbox.mjs:155` + `core/bridge.mjs:145`
- **证据等级**：已验证
- **触发条件**：对同一实例并发发起 ≥2 个 `bridge.call`（Agent 并行工具调用很常见）。
- **错误行为**：`drainResponses()` 无差别把 outbox 下**所有**响应文件 `rename` 到 `done/` 并返回；`waitForResponse()` 只认自己的 `requestId`，其余直接 `continue`（丢弃）。先完成 drain 的那个调用会消费并丢弃另一个调用的响应。
- **影响**：一个调用成功、另一个必然超时。复现结果：`[{ok:true,value:{echo:1}}, {ok:false,code:"timeout"}]`。**跨会话更严重**：两个 DSH 会话同时操作同一 Unity 实例时，会互相吞掉对方的响应，表现为随机超时与"操作没反应"。
- **关联**：`Bridge.call` 也未向下传 `onMismatch`，被丢弃时连审计都没有。
- **最小修复方向**：`waitForResponse` 改为「只取自己的响应，其余留在原地不动」：列出 outbox → 读 → 命中 `(id, instanceId, bootId, nonce)` 才 `rename` 到 `done` 并返回；未命中的文件不移动。另加按 mtime 的过期清理（>deadline 才删）。
- **关联优化任务**：AA-OPT-001

### [P1] AA-CONC-002 — 超时的请求仍留在 inbox，稍后会被执行 — `mailbox.mjs:70` + `probe/DSHBridgeProbe.cs.tpl`
- **证据等级**：已验证
- **触发条件**：调用超时（探针暂停、域重载、编辑器卡顿），随后探针恢复。
- **错误行为**：DSH 侧超时后不撤回请求（复现：`inboxAfterTimeout:["req_mwiwexbe_….json"]`）；探针模板中 `deadlineMs`/`issuedAt` **完全没有出现**（`probeChecksDeadline:false`），会无条件执行任何读到的请求。
- **影响**：典型场景 `unity.playmode.set {playing:true}` 在 30 秒后被延迟执行——用户已被告知失败并可能做了别的操作，编辑器状态却突然改变。这是"静默的延迟副作用"，比直接失败更危险。
- **最小修复方向**：① 探针在执行前校验 `now > issuedAt + deadlineMs` 则跳过并写一条 `expired` 响应；② DSH 侧超时后删除自己写入的 inbox 文件（best-effort）；③ inbox 加 TTL 清理。
- **关联优化任务**：AA-OPT-002

### [P1] AA-STATE-001 — 目标软件重启后缓存不刷新，表现为超时 — `core/bridge.mjs:78`
- **证据等级**：已验证
- **触发条件**：Unity 重启（`bootId` 换新），DSH 缓存里仍是旧实例。
- **错误行为**：`requireInstance()` 只在 `!instances.has(id)` 时刷新；已有缓存时继续用旧 `bootId` 写请求，新探针只轮询新目录 → 必然超时。复现：`restartCode:"timeout"`、`restartElapsedMs:819`（deadline 800ms）。
- **影响**：用户看到的是"超时"而不是"实例已重启，请重新发现"，会驱动 Agent 重试或误判。且旧 `bootId` 目录被 `ensureBootDirs` 重新创建，留下垃圾。
- **最小修复方向**：① `call` 前轻量重读 `instance.json`，`bootId/nonce` 变化则刷新实例并重试一次；② `targets()` 时清理不在本次发现结果中的实例。
- **关联优化任务**：AA-OPT-003

### [P1] AA-SEC-001 — 探针目录为符号链接时安装可越界写入 — `adapters/unity/index.mjs:44` + `safety/policy.mjs:44`
- **证据等级**：已验证
- **触发条件**：`<project>/Assets/DSHBridge` 已存在且是指向工程外目录的符号链接。
- **错误行为**：`assertInside()` 只用 `path.resolve` 做字符串前缀判断，不解析符号链接；`mkdir(dir,{recursive})` + `writeFile(dir/probe.cs)` 会写到链接目标。复现：`symlinkEscape:{err:null, wroteOutside:true}`。
- **影响**：越界写文件。攻击面是"能写工程的人已经能写工程"，但 `uninstall` 的 `rm(dir,{recursive})` 语义会因平台/实现差异带来额外不确定性；更现实的风险是用户工程里已有同名链接时的**意外覆盖**。
- **最小修复方向**：安装/卸载前 `lstat` 检查目标不是 symlink；写入用 `realpath` 后重新做 `startsWith` 校验；拒绝跨设备写入。
- **关联优化任务**：AA-OPT-004

### [P1] AA-DISCOVERY-001 — 未加引号的含空格工程路径被截断 — `adapters/unity/discover.mjs:31`
- **证据等级**：已验证
- **触发条件**：Unity 以 `-projectPath /tmp/my project`（未加引号）启动；macOS 上工程目录含空格很常见（`My Project`）。
- **错误行为**：正则 `(\S+)` 只取到 `/tmp/my`。复现：`spaceBare:"/tmp/my"`（正确应为 `/tmp/my project`）。
- **影响**：`instanceId` 基于错误路径计算 → 通道目录落在不存在的路径，`probeHeartbeat` 恒为 unprobed，用户看到"实例存在但永远装不上/连不上"，且错误难以自查。
- **最小修复方向**：`-projectPath` 后先按引号解析，无引号时取到下一个 `-` 开头参数之前的整段；再用 `ProjectSettings/ProjectVersion.txt` 存在性做校验，失败则回退 `lsof` cwd。
- **关联优化任务**：AA-OPT-005

### [P1] AA-TEST-001 — 回归目录 8 条 REG 指向不存在的测试文件 — `docs/03-quality/regression-catalog.md`
- **证据等级**：已验证
- **触发条件**：任何人按回归目录去定位用例。
- **错误行为**：静态对账结果——`REG-ISOLATION/ CAPABILITY/ INSTALL/ UNINSTALL/ DISCOVERY/ EVENTS/ RECOVERY/ EXTEND` 共 8 条指向 `tests/unit/router.test.mjs`、`tests/unit/capabilities.test.mjs`、`tests/e2e/uninstall.test.mjs` 等**不存在的文件**；实际用例分散在 `e2e/fake-editor.test.mjs` 与 `unit/safety.test.mjs`。

- **最小修复方向**：把 catalog 的测试文件列改为真实路径；补一个"REG 文件必须存在"的检查（加入 `npm run verify`）。
- **关联优化任务**：AA-OPT-006

### [P1] AA-EVENT-001 — 编译完成事件恒报成功 — `probe/DSHBridgeProbe.cs.tpl`（`OnCompilationFinished`）
- **证据等级**：已验证
- **触发条件**：工程编译失败。
- **错误行为**：`OnCompilationFinished` 无条件写 `{"ok": true}`；模板中不含 `scriptCompilationFailed`（`probeCompileFailureAware:false`）。
- **影响**：Agent 依据事件判断"编译成功"而继续下一步，实际脚本有错误。这是把失败伪装成成功，属于 skill 明令禁止的"错误的默认成功"。
- **最小修复方向**：用 `EditorUtility.scriptCompilationFailed`（或解析 `CompilationPipeline` 结果）填真实状态；事件里带上 `errorCount`。
- **关联优化任务**：AA-OPT-007

### [P2] AA-EVENT-002 — 事件目录无回收 — `transport/mailbox.mjs:143`

### [P2] AA-EVENT-003 — 身份文件损坏会导致事件游标永久错过 — `probe/DSHBridgeProbe.cs.tpl`（`LoadOrCreateIdentity`）
- **证据等级**：高置信推断
- **触发条件**：`instance.json` 被删除或 JSON 损坏（编辑器崩溃、磁盘满、外部清理）。
- **错误行为**：`_eventSeq` 归零，但文件编号仍从 `evt_0000000001` 重新开始；DSH 侧保存的游标可能远大于新序号，`readEvents` 过滤后永远返回空。
- **影响**：事件静默停止，用户以为没有编译/错误。
- **最小修复方向**：`bootId` 变化时把游标重置为 0；或事件文件名带 bootId 前缀，DSH 按 bootId 重置游标。
- **关联优化任务**：AA-OPT-012

### [P2] AA-PROTO-001 — 能力校验用适配器清单而非实例实际清单 — `core/bridge.mjs:132`

### [P2] AA-DOC-001 — OpenSpec 变更未归档，主规格与 delta 重复 — `openspec/`

### [P3] AA-PERF-001 — 每次 `bridge_targets` 全量 ps+lsof，加载时预热
- **证据等级**：已验证

### [P3] AA-PERF-003 — 探针每帧只处理一个请求

- **最小修复方向**：每帧处理到时间预算为止（如 8ms），长操作改为分帧/回调。

### [P3] AA-CODE-001 — 冗余代码与审计脱敏未实现

### [P3] AA-CODE-002 — `bridge_call` 输出 schema 拒绝数组返回值
- **证据等级**：高置信推断
- **触发条件**：某能力返回顶层数组。
- **错误行为**：output schema `data:{type:'object'}`，但 `execute` 只判断 `typeof data === 'object'`（数组也是 object）→ 数组被原样返回，随后 schema 校验可能失败。
- **影响**：新增能力时踩坑。
- **最小修复方向**：`Array.isArray` 时包一层 `{items}`，或 schema 用 `oneOf`。

## 测试与观测缺口

- **缺失用例**（本次直接相关的）：同实例并发调用、跨会话并发、超时后 inbox 残留、重启换 `bootId`、含空格工程路径、symlink 探针目录、编译失败事件、`probeOutdated` 下的能力拒绝。
- **缺失观测**：调用丢弃/配对失败只有可选 `onMismatch`，`Bridge` 未接；inbox 积压量、outbox 积压量、探针延迟分位数均无指标。
- **假覆盖**：8 条 REG 指向不存在文件；审计脚本不校验文件存在性。

## 残留风险

- 真实 Unity 未验证（本机无 Editor）：`InitializeOnLoad` 时序、域重载期间心跳空窗、`EditorApplication.update` 在 Play Mode 的行为，仍属未验证假设。
- `probeOutdated` 场景没有端到端用例，版本漂移的实际表现未知。
- 同机恶意进程可读 `instance.json` 拿到 `nonce`，"防伪造"只防误投递与跨用户，不防同用户；这一点在 SEC-0001 已披露，但 README/DETAIL 未告知终端用户。

## 总评

- **结论：条件通过（不建议直接对外发布）**。
- **理由**：P0 的并发丢响应会让 Agent 在"并行调用"这一常见模式下产生随机失败，并与 AA-CONC-002 的"延迟执行"叠加成难以诊断的状态错误。协议与隔离设计本身成立（四元组配对、原子投递、零端口均正确），缺陷集中在**消费语义**与**状态刷新**两个局部。
