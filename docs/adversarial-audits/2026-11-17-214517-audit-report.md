## 审计边界

- **范围**：文件邮箱通道的**请求处理与响应发布**全链路（探针 `Poll`/`HandleFile`/`PublishResponse`/
  `RecoverInterruptedRequests`/`SweepStaleOutbox`）、`requestHash`、`executionState`、`denied` 授权快照、
  以及 `scripts/bridge-cli.mjs`、`adapters/unity/{installer,activate,discover}.mjs`、`core/discovery.mjs`
- **方法**：只读代码审查 + 真机动态验证（P376 / Tuanjie 2022.3.61t15 / 探针 v11 `sourceHash=679959e8335a964d`）
- **威胁假设**：同机任意本地进程可读写 `Library/DSHBridge/**`（文件邮箱固有属性，已在前序报告确认无法认证）；
  目标不是身份认证，而是「不被越权写、不被静默解除配置、状态可判定」
- **不在范围**：跨机攻击、ASE/Unity 引擎自身缺陷、ASECLI 仓库内部实现

## 威胁与失败模型

- **资产**：工程内任意文件（含 `instance.json`）、探针的授权/拒绝快照、调用方对「是否已执行」的判断
- **最贵失败**：① 通道被当作越权写文件的入口；② 安全配置被工具静默解除；③ 已执行被报成未执行（或反之）导致重复副作用

## Findings 详情

### [P1] AA-SEC-101 — 校验请求 id，禁止其参与路径穿越

- **位置**：`DSHBridgeProbe.cs.tpl` → `HandleFile`（`id` 取值）与 `PublishResponse`（`Path.Combine(_outboxDir, id + ".json")`）
- **触发条件**：请求 JSON 里 `id` 含 `../`。
- **错误行为**：`Path.Combine` 不规范化 `..`，而 `WriteAtomic` 会先 `Directory.CreateDirectory` 再写。
  `id = "../../__dsh_escape_probe"` 从 `outbox/` 出发即落到 `Library/DSHBridge/`；`id = "../instance"`
  可直接覆盖 `instance.json`（实例发现文件）。
- **影响**：能写 `inbox/` 的进程可越权在工程内任意位置创建/覆盖 `.json`，包括伪造实例记录（进而影响 CLI/DSH 的实例判定）。
- **修复**：新增 `IsSafeRequestId`（`[A-Za-z0-9._-]`、≤128、禁 `..`），不合法即归档出队并留诊断，**不写 outbox**（id 不可信则响应文件名也不可信）。
- **验证**：投递 `id="../../__dsh_escape_v11"` → `Library/DSHBridge/__dsh_escape_v11.json` **未出现**。

### [P1] AA-SEC-102 — 让 CLI 安装继承而非清空 denied 快照

- **位置**：`scripts/bridge-cli.mjs` → `install` 分支
- **触发条件**：用户已配置 `bridge.denied`，随后用 CLI 重装探针。
- **错误行为**：`unityAdapter.install(...)` 的 options 只传 `allowDangerous`，`denied` 落到默认 `[]`，
  探针 `_deniedCapabilities` 被渲染为空——用户显式设置的「永久禁止」被一次普通重装静默解除。
- **影响**：安全配置失效且无提示；比直接提权更隐蔽（能力仍需 allowDangerous，但硬边界消失）。
- **修复**：默认**继承** `instance.json` 的 `deniedCapabilities`，仅 `--deny` 显式覆盖；安装返回与审计都带上 denied。
- **验证**：源码渲染已确认写入 `_deniedCapabilities = new string[] { "unity.asset.delete" }`；
  `install` 返回值 `deniedCapabilities=["unity.asset.delete"]`。心跳上报待重编译后确认。

### [P2] AA-DATA-101 — requestHash 改为基于原始字节

- **位置**：`HandleFile` 的 `resp["requestHash"]`
- **触发条件**：请求文件带 UTF-8 BOM。
- **错误行为**：原实现取 `File.ReadAllText`（已剥离 BOM）再重新编码，与调用方按**原文件字节**算出的摘要不一致，
  属于「文档说原始字节、实现算的是重编码字节」的契约偏差。
- **修复**：`File.ReadAllBytes` 保留原始字节，摘要基于它；解码仍剥离 BOM 供解析。
- **验证**：带 BOM 请求 → 调用方 `e8e5fab01746c273` == 探针返回同值。

### [P2] AA-LOGIC-101 — 孤儿恢复不得覆盖真实响应

- **位置**：`RecoverInterruptedRequests`
- **触发条件**：上次 `WriteAtomic` 成功但归档（`Finish` 的 `File.Move`）失败，导致 `outbox/<id>.json` 已有真实响应且 `in-progress` 残留。
- **错误行为**：恢复逻辑用 `WriteAtomic` 补写 `unknown`，而 `WriteAtomic` 先删后写，会把 `executed` 覆盖成 `unknown`——
  把「确认执行」降级成「不确定」。
- **修复**：补写前检查 `outbox/<id>.json` 是否已存在，存在则跳过。
- **验证**：预置 `in-progress` + 真实响应后触发域重载 → 响应仍为 `executionState="executed"`。

### [P2] AA-CLI-101 — 布尔 flag 不得吞位置参数

- **位置**：`scripts/bridge-cli.mjs` → `parseArgs`
- **触发条件**：`bridge-cli install --yes /path`（`--yes` 在前）。
- **错误行为**：解析器把 `/path` 当作 `--yes` 的值并消耗，`positional` 为空 → 回退到 `process.cwd()`，装错工程。
- **修复**：`BOOLEAN_FLAGS`（`yes/json/wait/help/dry-run`）强制视为 `true`，不消费下一个参数。
- **验证**：`inspect --json <path>` 正确解析到目标工程。

### [P2] AA-OPS-101 — 激活失败导致「装完不编译」

- **位置**：`adapters/unity/activate.mjs` → `activate`
- **触发条件**：macOS 未授予 Apple Events 自动化权限。
- **错误行为**：`osascript -e 'tell application "Tuanjie" to activate'` 失败（实测 `-609 连接无效`），
  `install` 的 `autoActivate` 静默失效 → 编辑器不刷新 → 探针永不编译，表现为「装了没生效」。
- **修复**：`open -a <app>` 兜底（走 LaunchServices，不需要 Apple Events 权限）。
- **验证**：`activate('Tuanjie')` 由抛错变为成功（走兜底分支）。

### [P2] AA-STALE-101 — 放宽陈旧阈值，并说明后台节流的真实边界

- **位置**：`WriteHeartbeat` 的 `staleAfterMs`
- **触发条件**：编辑器窗口失去焦点。
- **错误行为**：Unity 在后台会把 `EditorApplication.update` 降到极低频率甚至停跑（实测：切走后心跳停在 21:33，
  4 分钟后仍在原地）。原阈值 6000ms（2s×3）让实例迅速被判 `idle/stale`，调用方据此拒绝调用。
- **影响**：用户切到别的窗口后，ASECLI/DSH 的所有调用都会超时/被拒——但探针并未失效。
- **修复**：阈值放宽到 15s（7.5 倍心跳），让短暂切换不再误判；真死由 pid 存活判定兜底。
- **说明**：这不是探针缺陷，无法在协议层消除；文档须明确「长时间后台会停止心跳，调用前需让编辑器在前台」。

### [P3] AA-POLICY-101 — CLI 调用遵守 denied 快照

- `callCapability` 增加 denied 检查（读 `view.deniedCapabilities`），与插件侧 `bridge.denied` 语义一致，
  避免「走插件被拒、走 CLI 能用」。已修并写入审计。

## 测试与观测缺口

- `denied` 心跳上报（AA-SEC-102 的最后一环）需探针重编译后确认；当前证据为源码渲染 + 安装返回 + 编译通过。
- 无自动化用例覆盖「id 穿越」（当前为真机实测）。建议补离线用例：渲染探针后注入恶意信封，断言 `done/` 有归档而 `outbox/` 无写入。
- CLI 的 `--yes`/`--deny` 组合无自动化用例。

## 残留风险

- **编辑器后台即失效**：属引擎行为，已通过阈值与文档缓解，但无法根除。ASECLI 侧仍应把「长时间超时」优先归因为「编辑器不在前台」。
- **可伪造**：文件邮箱无法认证（前序已确认并接受）；本轮修复的是「越权写」与「静默解除配置」，不是认证。
- **v11 尚未在真机完整回归 V1–V5**：本轮修改了 `HandleFile` 主路径，需在编辑器前台时跑一次 `verify-bridge-capabilities`。
