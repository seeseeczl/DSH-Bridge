# REL-0003｜DSH-Bridge v0.0.6 发布记录

## 变更集合

- FR/CR/BUG/ADR：修复 BUG-0002（DSH 工具面三处输出/定位契约缺陷）。无新 FR、无 ADR 变更。
- 版本/提交/PR：工作区与插件包两处 `package.json` 均为 `0.0.6`；探针 `PROBE_VERSION` 保持 `12`（本次只动 DSH 侧，目标工程无需重装探针）。提交与 tag 见本记录所在提交。
- 兼容性说明：
  - `bridge_install` 输出契约不变（`dry_run` 字段集与 v0.0.5 相同），只是不再携带值为 `undefined` 的键——这些键本来也到不了消费方（DSH 校验直接拒绝）。
  - `bridge_knowledge_save` 输出字段集不变（`path/slug/topic/bytes`）；`updated` 从未成功透传到工具层，不构成移除已生效字段。
  - `bridge_knowledge_delete` 语义增强：主题原文与 slug 均可定位；不存在的主题如实返回 `removed: false`（此前可能误报 `true`）。无既有错误码变化。
  - `instance.json` 协议、工具数量（10 个不变）、探针能力表（44 项）均不变。
- 上游 RELPLAN / Flag 发布环：沿用第三段递增版本策略（0.0.5 → 0.0.6）；无 feature flag。
- 数据/架构迁移阶段与校验证据：无数据迁移。`core/knowledge.mjs` 新增 `removeTopic` 的标题回退与存在性校验；`tools/bridge-knowledge.mjs`、`tools/bridge-lifecycle.mjs` 各收窄一处输出契约。

## 验证与风险

- 测试/构建/审计证据：`npm test` 退出码 0——**134 项测试全绿**（较 v0.0.5 的 125 项新增 9 项，其中 5 项在修复前为红）；`npm run check:probe`（探针 csc 编译）退出码 0；`npm run check:docs`（文档一致性）退出码 0；`openspec validate --specs` 3/3 通过；`node scripts/check-openspec-state.mjs` 退出码 0。
- 真机验收证据：团结引擎 2022.3.62t7 隔离空工程上，44 项能力 57/57 用例通过（v0.0.5 已验）；本次修复后的工具面三条路径待 DSH 重启加载新代码后复验（见下「已知风险」）。
- 发布检查：架构检查脚本 `scripts/check_project_architecture.py` 在本机运行环境缺失（`npm run verify` 中该段无法执行），其余门禁逐项单独执行均通过；该缺失属本机环境问题，非本次变更引入。
- QCMD / SEC / OPS / SBOM / SLO 证据：QCMD-LOCAL-001（本地测试）、002/003（OpenSpec）通过；SEC-0001 无变更；OPS-0001 回滚手册沿用；SBOM 仍无第三方运行时依赖；SLO 沿用 OPS-0001。
- 已知风险与监控：
  - **修复需重启 DSH 才生效**：插件以 `link` 形式安装，`node_modules` 中的 JS 已被旧进程加载；重启后新的工具输出契约才生效。重启后需复验 `bridge_install dry_run`、`bridge_knowledge_save/delete` 三条真实链路。
  - `bridge_uninstall` 后运行中的编辑器在域重载前探针仍存活（`bridge_targets` 仍显示 `ready`），属引擎行为，已在验收记录中披露，未在本版本修改。
  - 同用户进程仍可读取通道 `nonce`，配对校验不防同用户恶意进程（SEC-0001 已披露，未变）。
- Go / No-Go 决定与负责人：Go，负责人 lead，决定时间 2026-11-18 22:50（+08:00）。依据：三个缺陷均有真实链路复现与「红→绿」证据，全部本地门禁（除环境缺失的架构检查段）退出码 0。No-Go 条件（引入新端口监听、协议破坏、探针不可卸载、回归测试缺失）均未出现。

## 回滚

- 触发条件：重启后工具输出仍被 DSH 拒绝，或知识库删除出现误删（按标题匹配命中错误文档）。
- 步骤：① DSH 侧回退到 v0.0.5（切回 tag `v0.0.5` 或 `install_bundle` 指向该目录快照）；② 探针无需回退（PROBE_VERSION 未变）；③ 知识库文件为纯本地 Markdown，无 schema 迁移，回退不丢数据。
- 验证：`bridge_install {dry_run: true}` 恢复为原先的「不可用但报错明确」状态即回退成功；`npm test` 125 项基线全绿。
- 迁移恢复、Flag 关闭与客户/消费者沟通：无数据迁移需恢复、无 flag。回滚建议在新版本修复而非撤回已发布 tag。
