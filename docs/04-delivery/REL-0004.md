# REL-0004｜DSH-Bridge v0.0.7 发布记录（能力补全）

## 变更集合

- FR/CR/BUG/ADR：新增 FR-0014（能力补全，用户指定缺口 1-7 全做、忽略协议生态与平台）。无新 ADR；ADR-0001（零端口）与 ADR-0002（单文件探针）不变。
- 版本/提交/PR：工作区与插件包两处 `package.json` 均为 `0.0.7`；探针 `PROBE_VERSION` 由 `12` 升至 `24`（已装探针需重装升级）。
- 能力面变化（44 → 77 项）：
  - 视觉反馈：`unity.screenshot.capture`（GameView/SceneView/相机 → PNG，落 `Library/DSHBridge/artifacts/`）；`unity.screenshot.sequence`（定间隔帧序列，录屏的帧序列等价物）。
  - 脚本精细编辑：`unity.script.get_sha`、`unity.script.apply_edits`（1-based 行列 patch、`preconditionSha256` 乐观锁、越界/重叠拒绝、原子落盘）；`unity.script.validate`（mono-mcs 编译校验，逐条诊断）。
  - 生产管线：`unity.build.start`（异步作业；输出禁止写 `Library/`，回传真实产物路径）、`unity.test.run`（动态编译桥接 TestRunnerApi，需工程安装 test-framework）、`unity.package.list/add/remove`（增删默认关闭）、`unity.bake.navmesh/lighting`。
  - 长任务作业化：`unity.job.list/status/cancel`；作业持久化到 `Library/DSHBridge/jobs/`，域重载后运行中的作业标 `interrupted`（不假装还在跑）。
  - 垂直域：`unity.graphics.quality/render_settings/stats`、`unity.profiler.status/set`、`unity.physics.settings/raycast`、`unity.animation.info/set`、`unity.vfx.particles/control`、`unity.ui.canvases`、`unity.probuilder.state`、`unity.sprite.info`、`unity.texture.generate`。
  - 原生交互（受管层）：`unity.window.list/focus`、`unity.input.send`（key/mouse/scroll 注入编辑器窗口）。系统级模态对话框需 OS 自动化，不在纯 C# 探针范围（Codely 用 native 实现），属已知边界。
  - 菜单执行：`unity.menu.execute` 从「探针侧永久封禁」降级为「可授权危险能力」（默认拒绝，`allowDangerous` 放行）。
- 兼容性说明：
  - 工具面 10 个不变；`bridge_targets` 能力清单由 44 项扩为 74 项，消费方应读取能力清单而非硬编码数量。
  - 危险能力清单新增 `unity.menu.execute`、`unity.package.add`、`unity.package.remove`（默认关闭，授权后可用）。
  - `PROBE_BLOCKED` 现为空；探针侧不再永久封禁任何能力（用户决策：能力与自由优先，风险由调用方承担）。
  - 探针源码变化较大，旧探针（v12-v21 之前）会被 `probeOutdated` 标记并拒绝调用，需重装。
- 数据/架构迁移：无数据迁移。新增能力集中在 `adapters/unity/probe/DSHBridgeProbe.cs.tpl` 与 `adapters/unity/index.mjs`；探针单文件形态不变（EXC-0001 例外仍适用）。
- 上游 RELPLAN / Flag：沿用第三段递增（0.0.6 → 0.0.7）；无 feature flag。

## 验证与风险

- 测试/构建/审计证据：`npm test` 退出码 0——**138 项测试全绿**（较 v0.0.6 的 134 项新增 4 项源码形态断言）；`npm run check:probe` 退出码 0；`npm run check:docs` 退出码 0（回归路径 36 条）；`openspec validate --specs` 3/3；`check-openspec-state` 退出码 0。
- 真机验证证据（团结引擎 2022.3.62t7，每批单独验证）：
  - 旧 44 项能力：57/57 用例通过（v0.0.6 基线）；v23 上再次回归 57/57 无退化。
  - 菜单解禁 + 截图：5/5（含真实 PNG 校验与非全黑确认）；脚本精细编辑：7/7（磁盘字节级校验）。
  - 生产管线与作业：9/10（构建产物 114MB `.app` 实存；作业域重载恢复专项另验通过）。
  - 垂直域第一批（图形/Profiler/物理）：8/8；垂直域第二批（动画/粒子/UI/ProBuilder/Sprite/纹理）：6/6；原生交互：6/6。
- 已知风险与边界：
  - `unity.build.start` 的构建在编辑器主线程同步执行：构建期间主线程被占用，作业查询要等构建结束后才响应（已如实披露）。
  - 纯 C# 探针无法可靠应答系统级模态对话框；`unity.input.send` 注入的是编辑器窗口事件，不是 OS 级输入。
  - `unity.package.add/remove` 会改工程依赖，默认关闭。
  - **测试运行依赖 test-framework**：`unity.test.run` 不在探针编译期引用 test-framework（预定义程序集无法引用其 asmdef，实测 CS0234），而是运行时动态编译桥接代码并显式引用 `Library/ScriptAssemblies/UnityEditor.TestRunner.dll`；工程未安装 test-framework 时返回 `test_framework_missing`。PlayMode 测试触发域重载时作业会被标记 `interrupted`。
- QCMD/SEC/OPS/SBOM/SLO：QCMD 本地测试通过；SEC 文档已同步危险能力清单与永久封禁清空；OPS 回滚沿用；SBOM 仍无第三方运行时依赖。
- Go/No-Go：Go，负责人 lead，2026-11-18 23:30（+08:00）。

## 回滚

- 触发条件：新探针在目标工程编译失败，或截图/构建/作业能力出现不可恢复异常。
- 步骤：① DSH 侧回退到 v0.0.6（切回 tag）；② 目标工程 `bridge_uninstall` 后重装 v0.0.6 探针（`PROBE_VERSION=14`）；③ 作业目录 `Library/DSHBridge/jobs/` 可安全删除（纯运行时产物）。
- 验证：`bridge_targets` 能力数回到 44/47 且状态 `ready`；`npm test` 回到 134 项基线全绿。
