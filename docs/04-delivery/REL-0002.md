# REL-0002｜DSH-Bridge v0.0.5 发布记录

## 变更集合

- FR/CR/BUG/ADR：修复 BUG-0001（`instance.json` 的 bootId 指向不存在的通道目录，导致 ASECLI 五个 Editor 命令持续 `bridge mailbox missing`）。无新 FR、无 ADR 变更。
- 版本/提交/PR：工作区与插件包两处 `package.json` 均为 `0.0.5`；探针 `PROBE_VERSION` 由 `11` 升至 `12`。提交与 tag 见本记录所在提交。
- 兼容性说明：
  - 协议 `v: 1` 与 `discoveryVersion: 1` 不变，`instance.json` 字段集不变（仅由探针侧保证其指向的目录必然存在）。
  - **`bridge_targets` 的 `status` 新增枚举值 `channel_missing`**，并新增 `channelOk` / `channelMissing` 两个字段。对 `status` 做穷举判断的外部消费方需补分支；走 `!== 'ready'` 否定判断的天然兼容。
  - 调用错误码新增 `channel_missing`（原为笼统的 `instance_not_ready`）。这是更精确的替代，未移除任何既有错误码。
- 上游 RELPLAN / Flag 发布环：沿用第三段递增版本策略（0.0.4 → 0.0.5）；无 feature flag。
- API/Event/客户端兼容矩阵与弃用窗口：工具面 8 个不变；探针能力表不变（42 项）；无弃用项。
- 数据/架构迁移阶段与校验证据：无数据迁移。DSH 侧新增模块 `packages/dsh-bridge/transport/channel.mjs`，将通道路径定义与目录体检从 `mailbox.mjs` 拆出（后者 283→238 LOC，回到 250 预警线下），`mailbox.mjs` 再导出 `channelRoot` / `bootPaths` 保持既有导入路径不变；无循环依赖。

## 回滚

- 触发条件：重装后出现新的通道异常、`channel_missing` 误报（目录实际齐全却判缺失）、或探针无法卸载。
- 步骤：① DSH 侧回退到 v0.0.4（`plugin_manager` 安装 `@local/dsh-bridge@0.0.4` 或切回 tag `v0.0.4`）；② 目标工程执行 `bridge_uninstall` 或删除 `<工程>/Packages/com.dsh.bridge/`；③ 清理 `<工程>/Library/DSHBridge/`；④ 若仅需止血，可保留 v0.0.5 而将探针回退为 v11（`channelOk` 判定对旧探针仍成立，因其同样读取真实目录）。
- 验证：`bridge_targets` 不再列出实例或状态回到 `ready`；编辑器进程无新增监听端口（`bridge-doctor` 断言）。
- 迁移恢复、Flag 关闭与客户/消费者沟通：无数据迁移需恢复、无 flag。回滚建议在新版本修复而非撤回已发布 tag。
