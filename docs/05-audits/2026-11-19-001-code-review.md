# AUD-CODE-001｜能力补全（v0.0.7/v0.0.8）代码审查报告

## 审查方式

- 3 个独立只读审查员按域并行审查（core/security、jobs/pipeline、domains/execution），不修改任何文件；Lead 独立复核关键结论并交叉验证。
- 覆盖：探针 9 个模板文件（6159 行）、DSH 侧 `probe.template.mjs` / `installer.mjs` / `safety/policy.mjs` / `core/*` / `tools/*`、测试与文档。
- 只读验证命令：`npm test`（141/141 通过）、`npm run check:probe`（多文件编译通过）；未启动编辑器。
- 行号基于 HEAD `b3fae39`（v0.0.8）。

## 结论摘要

- **P0：1 项**（MiniJson 无深度上限，可被深嵌套 JSON 触发不可捕获的栈溢出）。
- **P1：12 项**（安全边界 7 项 + 作业/生产管线 4 项 + 功能正确性 1 项）。
- **P2：约 35 项**（参数语义、资源约束、错误码一致性、状态机细节、文档/测试覆盖）。
- 总体：主干设计（授权快照、executionState、备份/恢复、路径统一入口）扎实；风险集中在「默认开启的写能力」「反射黑名单可绕过」「长任务语义」「序列化健壮性」。

## P0

### P0-1 MiniJson 递归无深度限制 → StackOverflow 杀死编辑器
- 位置：`packages/dsh-bridge/adapters/unity/probe/DSHBridgeProbe.MonoCompiler.cs.tpl`（`ParseValue` 递归，无深度参数）；调用点：主文件 `LoadOrCreateIdentity` 读 instance.json、`HandleFile` 读 inbox、Jobs 读作业文件。
- 问题：递归解析 `[`/`{` 无深度/节点数限制；.NET StackOverflowException 无法 catch，进程直接退出。
- 触发：向 `Library/DSHBridge/instance.json` 或当前 bootId 的 `inbox/*.json` 写入几十层以上嵌套 JSON（前者每次域重载/启动解析 → 崩溃循环）。
- 建议：`Parse` 增加 maxDepth（如 64）与输入字节上限（1 MiB），超限抛 FormatException；读文件前检查 `FileInfo.Length`；补语义测试。

## P1

### 安全边界

**P1-1 反射面黑名单可被链式绕过**
- 位置：`Capabilities.cs.tpl`（`EnsureTypeAllowed` 只校验当前 Type）、`Execution.cs.tpl`（ReflectMember 返回值句柄化）。
- 问题：`_deniedTypes`/`_deniedMembers` 只校验本次请求的目标类型/成员名；`System.Type`/`System.Reflection.*`/`System.Activator` 不在拒绝清单，`GetType`/`GetMethod`/`Invoke` 不在成员黑名单。已授权反射面可走 `Type.GetType → GetMethod → Invoke` 三步链执行被硬拒绝的 `AssetDatabase`/`Process` 等；`api.batch` 内嵌 `code` 亦可绕过 `bridge.denied` 对 `unity.code.execute` 的禁用。
- 建议：元编程类型加入拒绝清单（Type/MethodInfo/FieldInfo/ConstructorInfo/Assembly/Activator/Delegate），成员黑名单补 GetType/GetMethod/Invoke；batch 内嵌 code 做嵌套授权校验；补「handle 链绕过」语义测试。

**P1-2 默认开启的写能力可改写探针自身源码（提权）**
- 位置：`Capabilities.cs.tpl`（`AssetCreate` kind=script → `WriteTextAsset`）、`Assets.cs.tpl`（`ScriptApplyEdits`）、`Security.cs.tpl`（`ResolveProjectPath` 仅保证工程内）。
- 问题：`unity.script.apply_edits`（默认开启）与 `unity.asset.create`（默认开启）可写工程内任意文本（含 `.cs`），包括 `Packages/com.dsh.bridge/Editor/DSHBridgeProbe*.cs` → 编译后任意代码执行，绕过 `bridge.denied` 的「根本不允许」语义。
- 建议：显式拒绝写入 `Packages/com.dsh.bridge/**`；把「可执行代码写入」纳入危险能力/denied 语义；文档说明 denied 只按能力名生效。

**P1-3 路径闸门未覆盖 scene/build/job 入口**
- 位置：`Capabilities.cs.tpl`（`SceneOpen`/`SceneSave` 的 path 直传 Unity API）、`Jobs.cs.tpl`（`BuildStart.outputPath` 仅拒绝 Library/；`JobFile` 用 jobId 直接 Path.Combine）。
- 问题：违反「所有文件系统访问必须经 ResolveProjectPath」的声明；`jobId` 可含 `../`、绝对路径 → 读取工程外任意 `.json`（审查员用引擎 Mono 实测 `Path.Combine` 逃逸成立）；`scene.save` 可写工程外需实机确认。
- 建议：scene 路径走 `ResolveAssetPath` + `.unity` 限制；build outputPath 走 `ResolveProjectPath`（工程外需显式开关）；jobId 限定 `^job-[0-9a-f]{16}$` 且拼完路径做前缀校验；补语义测试。

**P1-4 通道目录/文件权限与文档承诺不符**
- 位置：主文件 `Init`（`Directory.CreateDirectory` 无权限设置）、`WriteAtomic`；文档 `docs/00-governance/security-data-governance.md`、`docs/DETAIL.md` 宣称 0700/0600。
- 事实：Lead 实测验证工程 `Library/DSHBridge` 为 0755、`instance.json` 为 0644；其他本机用户可读 nonce/pid/工程路径/事件。
- 建议：探针显式 chmod（P/Invoke libc，失败降级）；或文档改为「受 umask 影响」并登记残余风险。

**P1-5 探针侧授权闸门只覆盖 4 个反射能力**
- 位置：主文件 `_reflectCapabilities`/`EnsureCapabilityAllowed`；`safety/policy.mjs` `DEFAULT_DANGEROUS`（13 项）与文档。
- 问题：`asset.delete/move/rename/duplicate`、`importer.set`、`menu.execute`、`package.add/remove` 在探针侧无闸门；注释/文档却写「与 DEFAULT_DANGEROUS 保持一致、绕过 DSH 也会被拒绝」。
- 建议：要么全部纳入源码快照闸门，要么修正注释与三处文档（明确「探针侧仅对反射面设闸门，其余依赖 DSH 侧策略」）。

**P1-6 PublishResponse 吞掉 outbox 写失败**
- 位置：主文件 `PublishResponse`（写响应失败 `catch {}` 后仍归档 progress → done）。
- 问题：调用方收不到响应；progress 被移走使 `isInProgress=false` → 调用方可能按「未执行」安全重试 → 破坏性操作重复执行。
- 建议：写响应失败时不归档 progress（保留 in-flight 语义），或写 `executionState:"unknown"` 并留诊断。

**P1-7 事件序号回退与跨线程竞争**
- 位置：主文件 `Init`（复用 instance.json 的 eventSeq）、`PushEvent`、`WriteAtomic`。
- 问题：心跳每 2s 落盘 eventSeq；域重载前的最后事件会被 `probe_ready` 同号覆盖（编译事件丢失窗口 0~2s）；日志回调在任意线程，`_eventSeq += 1` 非原子可能同号覆盖。
- 建议：Init 取 max(instance.eventSeq, events 目录最大序号)；PushEvent 加锁或统一投递主线程。

### 作业与生产管线

**P1-8 PlayMode 测试结果永远拿不到**
- 位置：`Jobs.cs.tpl`（桥接回调注册/结果文件）、`PollTestJobs`（只处理 pending/running）、`RecoverInterruptedJobs`（一律 interrupted）。
- 问题：PlayMode 测试触发域重载 → 内存程序集回调丢失 → job 被标 interrupted 后不再轮询结果文件，测试实际跑完也拿不到结果；文档宣称支持 PlayMode。
- 建议：优先显式拒绝 playmode（`playmode_unsupported`，指向 Test Runner 窗口/CLI）并修文档；或恢复时对 test-run 重建桥接继续轮询。

**P1-9 构建失败/取消被记成 done**
- 位置：`Jobs.cs.tpl` `BuildStart` 的 advance（只把 `summary.result` 塞进 result，仍 `CompleteJob`）。
- 问题：`done` 应表达成功；调用方易误判。
- 建议：按 summary.result 分流 Succeeded→done、Failed→FailJob、Cancelled→cancelled。

**P1-10 bake.lighting 忽略 BakeAsync 返回 false**
- 位置：`Jobs.cs.tpl` `BakeLighting`。
- 问题：已有烘焙在跑时 `BakeAsync()` 返回 false 仍建作业；作业可能「假成功」，`job.cancel` 会调用 `Lightmapping.Cancel()` 误杀别人的烘焙。
- 建议：started=false 直接拒绝；记录启动归属，取消只对本作业生效。

**P1-11 test.run 可能永久 pending 且不可取消**
- 位置：`Jobs.cs.tpl`（桥接未实现 IErrorCallbacks；PollTestJobs 无超时；cancelable=false）。
- 建议：实现 OnError 写结果；增加作业超时兜底；允许取消或文档说明。

### 功能正确性

**P1-12 screenshot.sequence 可阻塞主线程约 100 分钟**
- 位置：`Assets.cs.tpl`（count≤600 × intervalMs≤10000，循环内主线程 Sleep）。
- 问题：组合上限无总时长约束，编辑器完全无响应；DSH 30s 超时后形成超时风暴。
- 建议：总时长预算（如 ≤10s）；或改为作业化逐帧推进（可取消）。

## P2（按主题，详见三份独立审查记录）

- **序列化/协议**：NaN/Infinity 输出非法 JSON（响应丢失且副作用已发生）；无界文件读取（inbox/instance/jobs）；WriteAtomic 非原子 + tmp 残留；MiniJson 尾逗号 IndexOutOfRange。
- **参数语义**：ToBool 与 ToBoolValue 不一致（"1"/数字）；Enum.Parse 接受数字未定义值；缺参静默默认值导致破坏性动作（playmode.set 缺 playing 会停止播放、setActive 缺 active 会禁用对象、quality 缺 level 切到 0）；未知 change 键静默忽略却回 applied。
- **写能力**：asset.create 静默覆盖既有文件（无 overwrite/precondition）；scene.open 丢弃未保存改动 + mode 拼写错误静默降级；prefab.create 覆盖已有路径；gameobject.create 失败留孤儿对象；setParent 无 Undo；prefab.close 可能丢弃未保存修改。
- **读能力**：material.get/hierarchy.list/object.find/api.members 等截断无统一标记；asset.find 空 filter 全库枚举无预算；asset.read 整文件读取。
- **反射/执行面**：DescribeEx 标量类型缺口（short/byte/uint/char 变 $handle）；api.invoke 与 reflect.invoke 的参数转换不对称；异常→错误码映射过窄（IO/Format/InvalidCast→probe_error）；batch Undo 组不恢复不折叠；每次 code.execute/validate 泄漏一个不可卸载动态程序集；显式 references 不存在被静默丢弃。
- **截图/原生交互**：target=game 是 Camera.main 渲染而非 GameView（多相机/Overlay UI 不一致）；8192² 峰值数百 MB、无容量清理、同毫秒文件名覆盖；SendEvent 返回值被忽略、键盘无 character/modifiers、鼠标无 clickCount、滚轮无位置、窗口按类型匹配歧义。
- **作业**：作业记录无上限/无清理/每帧全量遍历；持久化非原子；cancel 语义过宽（不校验终态、不持久化、无 cancelling）；CreateJob 后异常留下永久 pending；package.add/remove 域重载一律 interrupted（实际已成功）；构建产物探测缺 .apk/.aab；Library 预检依赖 CWD 且大小写敏感；TargetInvocationException 未解包；并发 test.run 无互斥；navmesh 未作业化；test-run 不进入 running、progress 不更新。
- **安装器（DSH 侧）**：多文件写入非原子（入口文件先写，中断会留半更新状态）；不清理模板外的旧 `DSHBridgeProbe*.cs`（降级/回滚会 CS0101）；`uninstallProbe` 以主文件存在判断（部分残留时不删目录）；e2e/install 测试硬编码 files 数量 10。
- **文档/测试**：README「审计覆盖全部 6 个工具」过时（现 10 个）；新能力回归以「源码字符串存在性」为主，语义 harness 未覆盖截图/apply_edits/validate/垂直域/窗口输入；真机验收部分断言偏 smoke（validate 用 .txt 只断言 boolean、input.send 只断言 applied 长度）；权限/argv 旁路等承诺与实现不符。
- **其他**：Roslyn 后端不返回 warningCount（mono 返回，字段不一致）；Enum.Parse 未包装 KnownError；ToProjectRelative 越界兜底返回绝对路径；IsInsideProject 大小写敏感（macOS 误拒）；SweepStaleBootDirs 按目录 mtime 可能误删活跃通道；_scanning 死代码；Init 失败无自愈；死代码 GrantedCapabilitiesForTest/DangerousCapabilitiesForTest（后者只返回 4 项）。

## 未发现问题的区域（覆盖度说明）

- 截图资源释放（RenderTexture/相机状态 finally 恢复）；apply_edits 行列换算与逆序应用、重叠/越界拒绝、原子写（BOM/CRLF 例外见 P2）。

- npm test 141 项与 check:probe 全绿；DSH 侧授权默认拒绝与 probeOutdated/capability_unsupported 前置拦截。
