# ADR-0001｜用文件邮箱实现零端口双向通道

## 背景与约束

用户要求：DSH 是唯一发起方；目标软件侧不开 TCP 监听端口；不部署 MCP server；多实例不串台。同时要"最大程度接管"目标软件能力。

约束的交集意味着：通道必须是一种**双方都能访问、但不需要任何一方 listen** 的介质，且能承载请求-响应配对。

## 备选方案

| 方案 | 好处 | 成本/风险 | 不采用原因 |
| --- | --- | --- | --- |
| 文件邮箱（原子写 + 轮询） | 零端口、零服务、天然可审计、崩溃后状态可恢复 | 延迟 50–200ms；需去重 | —（采用） |
| Unix Domain Socket | 低延迟、真双向流 | 需 B 端 listen；socket 残留；跨平台 | 违反"B 端不主动开启"；作为可选加速层 |
| TCP + MCP server | 生态标准 | 端口管理、安装成本、串台风险 | 用户明确排除 |
| 共享内存 / 命名管道 | 低延迟 | 平台差异大、可移植性差 | 复杂度不划算 |

## 决定与理由

采用**文件邮箱**作为默认且唯一必需的传输层：

- 目录布局：`<channelRoot>/<adapter>/<instanceId>/<bootId>/{inbox,outbox,events}`，权限 `0700`。
- 原子性：写 `.tmp` → `fsync` → `rename()`；消费方 `rename()` 到 `done/` 后处理，保证至多一次。
- 配对：请求与响应均携带 `v / id / instanceId / bootId / nonce`，四元组不匹配即丢弃并审计。
- 超时：调用方按 `deadlineMs` 截止；迟到响应按 `issuedAt` 判过期并清理。
- 加速层可选：配置开启 UDS 时，语义与文件通道完全一致，可随时关闭回退。

理由：它是唯一能同时满足"零端口 + 零服务 + 可逆 + 跨平台"的介质；性能缺口由"可选加速层"而非"改默认架构"解决。

## 后果、兼容性与回滚

- 正面：无端口冲突；多实例天然按目录隔离；通道内容可人工检视、可重放。
- 负面：引入轮询延迟；需要严格的去重与清理策略；依赖文件系统语义（需原子 rename）。
- 兼容性：协议带 `v` 字段；新增字段必须可选，旧探针忽略未知字段。
- 回滚：删除通道目录即清空状态；关闭插件即停止所有轮询。

## 复审日期与例外到期日

复审 2026-12-15；若实测 p95 延迟超过 500ms，则把 UDS 提升为默认并重开本 ADR。
